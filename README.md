# Telegram News Bot

Бот автономно ведёт новостной Telegram-канал про AI и технологии: собирает новости
из RSS, выбирает самую интересную, пишет по ней авторский пост, проверяет его
редактором и ревизором, рисует картинку и публикует по расписанию. По статистике
опубликованных постов определяет лучшее время публикации.

## Как запустить

Основной вариант — хостинг (например, bothost): **всё настраивается переменными
окружения**, файл `.env` не нужен и на сервер его копировать не надо.

Команда запуска: `python main.py`

Требуется Python 3.10+ и зависимости из `requirements.txt`.

```powershell
pip install -r requirements.txt
python main.py
```

Проект запускается одним процессом: `main.py` поднимает и Telegram-бота, и планировщик.
Второй экземпляр запустить нельзя — бот блокирует повторный старт, потому что два
процесса писали бы в одну базу и публиковали дубли.

Остановка — `Ctrl+C` или сигнал остановки от хостинга: бот корректно останавливает
планировщик и соединение с Telegram.

При локальном запуске те же переменные можно положить в `.env` — он подхватывается
автоматически, но переменные окружения имеют приоритет. Учтите: `load_dotenv()`
ищет `.env` не только в текущей папке, но и выше по дереву каталогов.

Эмодзи в логе не сломают запуск: в `cmd` консоль по умолчанию cp1251, но бот сам
переключает вывод на UTF-8 (команду `chcp` и переменные задавать не нужно).

## Переменные окружения

Обязательные — без них бот не стартует и печатает, чего именно не хватает:

| Переменная | Смысл |
|---|---|
| `TELEGRAM_TOKEN` | токен бота от @BotFather |
| `CHANNEL_ID` | id канала: числовой (`-100...`) или `@username` |
| `DEEPSEEK_API_KEY` | выбор новости, рерайт, редактура |
| `ODIROUTER_API_KEY` | генерация картинок (Kling 1.0) |

Необязательные — при отсутствии берётся значение по умолчанию:

| Переменная | По умолчанию | Смысл |
|---|---|---|
| `ADMIN_ID` | — | id администратора. Без него команды открыты всем — бот предупредит об этом при старте |
| `ADMIN_IDS` | — | дополнительные админы через запятую: `111,222` |
| `OWNER_CHAT_ID` | — | дополнительный id с правами админа |
| `NEWSAPI_KEY` | — | дополнительный источник новостей |
| `POST_INTERVAL` | `10800` | минимальный интервал между автопубликациями, сек |
| `MIN_POST_LENGTH` / `MAX_POST_LENGTH` | `300` / `950` | границы длины поста |
| `MAX_REWRITE_ATTEMPTS` | `5` | попыток доработки поста |
| `PARSER_CONCURRENCY` | `8` | сколько RSS-лент парсить одновременно |
| `POST_COOLDOWN` | `600` | пауза между ручными запусками из Telegram, сек |
| `USE_LEARNED_BEST_PRACTICES` | `true` | подсказывать рерайтеру наблюдения из статистики |
| `PUBLISH_TIME_RESERVE` | `120` | резерв времени: если его не хватает, пост публикуется без картинки |
| `DB_PATH` | `news_bot.db` | путь к базе |
| `MEMORY_PATH` | `memory_bank` | папка памяти агентов |

Битые значения не роняют старт: `ADMIN_ID=abc` превратится в 0, `POST_INTERVAL=девять`
— в значение по умолчанию.

**Важно про хранение данных.** `news_bot.db` и `memory_bank/` — это состояние бота.
Если хостинг пересобирает контейнер, задайте `DB_PATH` и `MEMORY_PATH` на
смонтированный постоянный диск, иначе история постов, статистика и выученные
практики будут теряться при каждом обновлении.

`CHANNEL_ID` может быть числовым id (`-100...`) или `@username`. Для сбора
просмотров нужен @username канала: бот получает его сам через `getChat`, но это
сработает только для публичного канала. Просмотры берутся с публичной страницы
`t.me/<username>/<message_id>`, потому что Bot API не отдаёт статистику
конкретного сообщения.

## Команды бота

| Команда | Что делает |
|---|---|
| `/start` | главное меню с кнопками |
| `/post` | собрать и опубликовать пост сейчас (без ожидания генерации картинки) |
| `/status` | опубликовано / в очереди, время последней публикации, состояние планировщика |
| `/analytics` | собрать статистику и показать сводку |
| `/admin` | очистка старых постов и перезапуск планировщика |
| `/help` | справка |

## Как устроено

```
main.py
 ├── TelegramBot (telegram_bot.py) ── /post ──► Orchestrator   [ручной цикл]
 └── Orchestrator.run_scheduler()
        └── SchedulerAgent ──раз в 30 мин──► Orchestrator.run()  [автоцикл]
                                                │
   Парсер → Селектор → ┌ Рерайтер → Редактор → Ревизор ┐ (до MAX_REWRITE_ATTEMPTS)
                       └────────── feedback ───────────┘
                     → ImageAgent → PublisherAgent → AnalyticsAgent
                                                │
                    MemoryBank (memory_bank/*.json) ◄── практики и лучшее время
                                                │
                                    SQLite news_bot.db (posts / logs / post_stats)
```

Все агенты наследуют `agents/base_agent.py` и обмениваются данными через общий
словарь `context`. Агенты:

| Агент | Файл | Роль |
|---|---|---|
| Парсер | `agents/parser_agent.py` | обходит RSS и NewsAPI параллельно, отсекает уже опубликованное |
| Селектор | `agents/selector_agent.py` | выбирает лучшую новость через DeepSeek |
| Рерайтер | `agents/rewriter_agent.py` | пишет пост и промпт для картинки |
| Редактор | `agents/editor_agent.py` | сокращает переросший пост |
| Ревизор | `agents/reviewer_agent.py` | чек-лист качества: длина, эмодзи, прогноз, запрещённые слова |
| Генератор картинок | `agents/image_agent.py` | Kling 1.0 через OdiRouter |
| Публикатор | `agents/publisher_agent.py` | пишет в БД, шлёт в канал, сохраняет `message_id` |
| Аналитик | `agents/analytics_agent.py` | собирает просмотры/реакции, ищет закономерности, считает лучшее время |
| Планировщик | `agents/scheduler_agent.py` | решает, когда публиковать |

Ключевые нюансы, о которые легко споткнуться:

- **Время.** SQLite пишет `published_at` в UTC, весь остальной код — в локальном
  времени. Читать эту колонку можно только через `parse_db_timestamp()`, иначе
  «лучшее время публикации» уезжает на величину смещения.
- **Контракт отчёта аналитики** — `{"hour", "day", "interval_hours", "reason"}`,
  читать только через `normalize_analytics_report()`.
- **Ревизор не блокирует публикацию.** Пост публикуется даже с замечаниями, а
  одобрение с первой попытки — метрика качества.
- **Память общая для процессов.** `MemoryBank` перечитывает файл при каждом
  обращении, иначе агент не увидит записи других агентов до перезапуска.
- **Просмотры** доступны только для постов, у которых сохранён `message_id`
  (посты до появления этой колонки пропускаются). Если данных нет — статистика
  не пишется вовсе, выдуманных чисел в базе не бывает.

## Проверки

Скрипты запускаются вручную (`python test_<имя>.py`), каждый печатает отчёт и
возвращает ненулевой код при провале. Они работают на временной БД и временной
памяти, реальные данные проекта не меняются.

| Скрипт | Что проверяет |
|---|---|
| `test_scheduler_time.py` | контракт времени: Аналитик → память → Планировщик |
| `test_metrics.py` | миграция схемы, `message_id`, сбор реальных просмотров из `t.me` |
| `test_improvements.py` | таймзона, неблокирующий HTTP, практики, UTF-8, Config, память |
| `test_final.py` | дедуп, публикация без картинки, ревёрс-цикл, метка ручного запуска, UI, запуск через переменные окружения |
| `test_parser.py`, `test_selector.py`, `test_rewriter.py`, `test_reviewer.py`, `test_publisher.py`, `test_analytics.py`, `test_orchestrator.py` | отдельные агенты (ходят в реальные сети/API) |

## Известные ограничения

- Просмотры берутся парсингом HTML `t.me`: если Telegram поменяет вёрстку —
  аналитика перестанет собираться (без падений, просто не будет данных).
- `clicks`, `shares` и дочитываемость из публичного превью недоступны, поэтому
  оценка поста строится на просмотрах и реакциях.
- Практики выводятся из оценки, а оценка — из просмотров; посты в канале с малой
  аудиторией дают слабый сигнал, поэтому статистика используется как подсказка,
  а не как жёсткое правило.
- Старые посты удаляются через 30 дней (`clean_old_posts(30)`) вместе со
  статистикой; дедуп по ссылкам рассчитан на суточное окно, поэтому не уменьшайте
  срок хранения меньше суток.
